# 新手入门：Tauri 应用开发、调试与真机部署指南

**适用项目**：大盘行情看板（Tauri v2 + Vue 3）
**面向读者**：不了解 Tauri 和 Cargo 的新手
**更新日期**：2026-08-31

---

## 一、先搞懂三个基本概念

### 1. 这个项目由两部分组成

```
┌─────────────────────────────────┐
│  前端（你看到的界面）              │
│  Vue 3 + TypeScript 编写         │
│  位于 src/ 目录                  │
└──────────────┬──────────────────┘
               │ 通过 invoke 调用
┌──────────────▼──────────────────┐
│  后端（获取行情数据的程序）        │
│  Rust 语言编写                   │
│  位于 src-tauri/ 目录            │
└─────────────────────────────────┘
```

- **前端**用 JavaScript 写，浏览器直接运行
- **后端**用 Rust 写，需要"编译"成机器码才能运行——编译它的工具就是 **Cargo**（Rust 的包管理器 + 编译器，类似前端的 npm）
- **Tauri** 是把这两者打包成一个 App 的框架（类似 Electron，但更轻量）

### 2. 两种运行模式

| 模式 | 用途 | 特点 |
|---|---|---|
| **开发模式（dev）** | 写代码时用 | 界面改动秒级刷新（热更新）；界面来自电脑上的开发服务器 |
| **发布模式（release）** | 装到手机上正式用 | 所有资源打包进 App；启动快、不依赖电脑 |

> **为什么真机不能用开发模式？** 开发模式下 App 会去连接"电脑上 1420 端口的开发服务器"。手机连的 localhost 是它自己，不是你的 Mac，所以会报 `localhost:1420` 错误。**真机上请一律使用发布模式。**

### 3. 三个常用的命令入口

| 命令 | 是什么 | 干什么 |
|---|---|---|
| `pnpm` | JavaScript 包管理器 | 安装依赖、启动前端 |
| `cargo` | Rust 的编译器管理工具 | 编译后端代码（通常不用手动敲，被其他命令自动调用） |
| `pnpm tauri` | Tauri 的总指挥 | 一条命令同时搞定前端 + 后端 + 打包 |

## 二、第一次运行前（只需做一次）

打开「终端」（Terminal），逐行执行：

```bash
# 1. 进入项目目录
cd ~/gitlab/hq-kanban-app

# 2. 安装前端依赖
pnpm install

# 3. 安装 Rust 的 iOS 编译支持（各执行一次）
rustup target add aarch64-apple-ios        # 真机用
rustup target add aarch64-apple-ios-sim    # 模拟器用
```

## 三、日常开发：在 Mac 电脑上调试

写代码时最常用的命令，就这一条：

```bash
pnpm tauri dev
```

**执行后会发生什么**：
1. 自动打开一个桌面窗口，显示行情看板
2. 你修改 `src/` 下的任何代码（界面、样式），窗口会**自动刷新**
3. 按 `Ctrl + C` 停止

> 首次运行会编译 Rust 代码，可能需要几分钟，之后秒启动。

**桌面窗口小知识**：
- 窗口顶部有一条自定义标题栏，可以直接**拖动窗口**（按住标题栏拖）
- 标题栏右侧是最小化/关闭按钮，与普通 Mac 窗口一致
- 开发模式下窗口标题为「大盘行情看板」，尺寸 900×680

### 在 Mac 上安装正式版（发布模式）

开发模式调试完，想把自己电脑上当正式 App 用，执行：

```bash
pnpm tauri build
```

**执行后产物位置**（`src-tauri/target/release/bundle/`）：

| 产物 | 用途 |
|---|---|
| `macos/大盘行情看板.app` | 双击即可运行；也可拖入「应用程序」文件夹安装 |
| `dmg/大盘行情看板_0.1.0_aarch64.dmg` | 标准安装镜像，可发给其他人安装 |

**两种安装方式**：

```bash
# 方式一：直接运行构建出的 App
open src-tauri/target/release/bundle/macos/大盘行情看板.app

# 方式二：挂载 DMG 安装（双击 dmg 后把 App 拖入 Applications）
open src-tauri/target/release/bundle/dmg/
```

安装后即可在「启动台/应用程序」中找到**大盘行情看板**，像普通 Mac 软件一样使用，无需再开终端。

> **开发模式 vs 正式版的区别**：开发模式（dev）需要终端保持运行、依赖电脑上的开发服务器；正式版（build）是独立完整的 App，双击即开，适合日常使用和分发。

## 四、运行到 iPhone 模拟器

适合快速看移动端效果，无需真机。

### 方式一：一条命令（推荐新手）

```bash
pnpm tauri ios dev
```

**执行后**：自动启动 iPhone 模拟器并安装运行 App，改代码自动刷新。

> 如果提示选择设备，用方向键选择 iPhone 17 等模拟器后回车。

### 方式二：Xcode（能看到崩溃详情）

```bash
# 用 Xcode 打开 iOS 工程
open src-tauri/gen/apple/hq-kanban-app.xcodeproj
```

然后在 Xcode 里：
1. 顶部工具栏选择 **iPhone 17**（设备下拉框）
2. 确认 scheme 旁的配置是 **debug**
3. 点击 **▶ Run**（或按 `Cmd + R`）

> Xcode 的好处：App 崩溃时会停在出错的代码行，方便排查。

## 五、运行到 iPhone 真机（发布模式）

### 前提条件

1. iPhone 用数据线连接 Mac
2. iPhone 上信任了此电脑（首次连接时手机会弹窗）
3. Xcode 中签名配置正确（本项目已配置好，一般不用动）

### 一键脚本方式（推荐）

把下面整段复制到终端执行（一条条粘贴也行）：

```bash
# 第 1 步：进入项目目录
cd ~/gitlab/hq-kanban-app

# 第 2 步：构建前端界面资源
pnpm build

# 第 3 步：清理旧缓存并重新生成 Xcode 工程
export PATH="$HOME/.rustup/toolchains/stable-aarch64-apple-darwin/bin:$HOME/.cargo/bin:$PATH"
cd src-tauri
cargo clean --target aarch64-apple-ios --release
cd gen/apple
xcodegen generate

# 第 4 步：编译整个 App（Rust 编译约 3 分钟，请耐心等待）
DEVICE_UDID="00008150-000A31163407801C"   # ← 换成你自己手机的 UDID
xcodebuild -project hq-kanban-app.xcodeproj \
  -scheme hq-kanban-app_iOS \
  -configuration release \
  -destination "id=$DEVICE_UDID" \
  -allowProvisioningUpdates build

# 第 5 步：把 App 装到手机上
APP="$HOME/Library/Developer/Xcode/DerivedData/hq-kanban-app-*/Build/Products/release-iphoneos/大盘行情看板.app"
xcrun devicectl device install app --device $DEVICE_UDID $APP

# 第 6 步：启动 App
xcrun devicectl device process launch --device $DEVICE_UDID com.huafu.hqkanbanapp
```

**怎么看自己手机的 UDID**：
```bash
xcrun xctrace list devices
# 输出中带 (27.0) 之类版本号、不带 Simulator 字样的就是真机
# 括号里的那串 40 位字母数字就是 UDID
```

### Xcode 图形界面方式（点鼠标就行）

```bash
open src-tauri/gen/apple/hq-kanban-app.xcodeproj
```

在 Xcode 里：
1. 顶部设备下拉框选择你的 iPhone（如 **贾少英17PM**）
2. 点击 scheme 名 → **Edit Scheme → Run → Info**，把 Build Configuration 改为 **release**
3. **Product → Clean Build Folder**（`Shift + Cmd + K`）
4. 点击 **▶ Run**

> **重要**：真机调试请始终用 **release** 配置。如果用 debug，App 会因为连不上开发服务器而白屏/报错。

## 六、发布打包（生成可分发的 IPA）

```bash
cd ~/gitlab/hq-kanban-app
pnpm tauri ios build --ignore-version-mismatches --ci --export-method debugging
```

产物位置：`src-tauri/gen/apple/build/arm64/大盘行情看板.ipa`

> IPA 相当于 iOS 的安装包，可通过 Apple Configurator 或 Xcode 装到其他测试设备上。

## 七、出问题了怎么办？

### 常见错误对照表

| 屏幕上看到 | 意思是 | 怎么办 |
|---|---|---|
| `Failed to request http://localhost:1420/` | App 在用"开发模式"找电脑要界面 | 真机要用 release 构建（见第五节） |
| `EXC_BAD_ACCESS` 启动就闪退 | App 还没跑到你的代码就挂了 | 用 Xcode 打开工程运行，看停在哪一行 |
| `No code signature found` | 安装包没签名 | 用带签名的构建（不要加 `--no-sign`） |
| `Failed Registering Bundle Identifier` | App 的"身份证号"被别人注册了 | 需要换一个 Bundle Identifier |
| `No Account for Team` | 签名团队和 Xcode 登录的账号不匹配 | Xcode → Settings → Accounts 检查登录账号 |

### 万能三步重置法

构建出现诡异问题时，按顺序执行（相当于"重启大法"）：

```bash
# 1. 清掉所有编译缓存
cd ~/gitlab/hq-kanban-app
rm -rf ~/Library/Developer/Xcode/DerivedData/hq-kanban-app-*
export PATH="$HOME/.rustup/toolchains/stable-aarch64-apple-darwin/bin:$HOME/.cargo/bin:$PATH"
cd src-tauri && cargo clean

# 2. 重新生成 Xcode 工程
cd gen/apple && xcodegen generate

# 3. 重新构建（回到第五节执行第 4 步开始的命令）
```
